# stu-pytorch

一个用于学习 PyTorch 计算机视觉模型的验证码识别项目。项目按三个阶段推进：

1. **第一阶段：使用 DenseNet121 初尝 CNN 识别**——借助 ImageNet 预训练模型，从整张图片直接预测 4 个字符。
2. **第二阶段：实现一个简单 CNN**——使用 `nn.Conv2d` 等基础组件自己搭建网络，理解卷积网络的结构和训练过程。
3. **第三阶段：实现可变长度验证码识别**——使用 CNN 提取横向视觉特征，结合 BiLSTM 与 CTC 在无需字符切分的情况下识别 2～6 位验证码，理解序列建模与自动对齐。

## 第一阶段：DenseNet121

当前第一阶段使用 ImageNet 预训练的 DenseNet121，从整张图片直接预测 4 个字符，
不进行字符切割。

### 当前模型

- 输入：RGB 图片，统一缩放为 `180 × 100`
- 配置字符集：`0-9` 和 `a-z`，共 36 类
- 输出：`4 × 36 = 144` 个分数
- 训练集：`data/train`，800 张
- 验证集：`data/test`，381 张
- 权重：`stage1_densenet121/checkpoints/model-36.pth`
- 整图准确率：4 个字符全部正确的图片数 ÷ 图片总数
- 单字符准确率：预测正确的字符位置数 ÷ 字符位置总数

当前数据文件名均为 4 个字符，例如 `25mb.png`。文件名（不含扩展名）就是监督
标签。当前数据实际只覆盖 `2345678abcdefgmnpwxy` 这 20 个字符，因此训练出的
权重不能视为可靠支持全部 36 类。数据目录中只能放符合该规则的图片文件。

## 环境准备

项目需要 Python 3.13 和 [uv](https://docs.astral.sh/uv/)：

以下命令都需要在项目根目录执行，因为数据和权重使用相对路径。

```bash
uv sync
```

项目使用 `uv.lock` 固定依赖版本。

macOS 运行 Tkinter GUI 还需要：

```bash
brew install python-tk@3.13
```

PyTorch 会自动选择可用设备，顺序为 CUDA、Apple MPS、CPU。默认首次训练会下载
DenseNet121 的 ImageNet 预训练权重，之后使用本机缓存；使用 `--no-pretrained` 时不会下载。

## 代码格式与检查

项目使用 Ruff 统一检查和格式化 Python 代码。Ruff 作为开发依赖记录在 `pyproject.toml`
和 `uv.lock` 中，执行 `uv sync` 时会一并安装。

```bash
# 检查代码问题
uv run ruff check .

# 自动修复可以安全修复的问题
uv run ruff check . --fix

# 格式化代码
uv run ruff format .

# 只检查格式，不修改文件
uv run ruff format --check .
```

提交代码前推荐运行：

```bash
uv run ruff check . && uv run ruff format --check .
```

当前启用了常见代码错误、未使用代码、import 排序、现代 Python 写法和 bug-prone
模式检查，目标 Python 版本为 3.13，默认行宽为 88。

## 训练

当前推荐基线：

```bash
uv run python -m stage1_densenet121.train --loss multi-label --lr 0.001 --backbone-lr 0.0003
```

训练 30 轮，每轮评估一次，同时输出整图准确率和单字符准确率。只将验证整图准确率
最高的权重保存到 `stage1_densenet121/checkpoints/model-36.pth`；整图准确率相同时保留
loss 更低的权重。

两个阶段共用的 `--epochs`、`--batch-size`、`--lr` 和 `--plot-curves` 由
`training_config.py` 中的 `TrainingConfig` 统一定义和校验。两个阶段可以分别设置默认值。
曲线绘制逻辑统一放在 `training_curves.py` 中。

可用参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--epochs` | `30` | 训练轮数 |
| `--batch-size` | `5` | 每批图片数量 |
| `--loss` | `multi-label` | `multi-label` 或 `cross-entropy` |
| `--lr` | `0.001` | 分类层学习率；不设置主干学习率时也是全模型学习率 |
| `--backbone-lr` | 未设置 | 单独指定 DenseNet 特征主干学习率 |
| `--classifier-only` | 关闭 | 冻结 DenseNet 特征层，只训练分类层 |
| `--no-pretrained` | 关闭 | 不加载 ImageNet 预训练权重，从随机初始化开始训练 |
| `--plot-curves` | 关闭 | 实时显示训练集/验证集的 loss、整图准确率和单字符准确率曲线 |

示例：

```bash
# 只训练最后一层
uv run python -m stage1_densenet121.train --classifier-only --loss multi-label --lr 0.001

# 主干和分类层使用不同学习率
uv run python -m stage1_densenet121.train --loss multi-label --lr 0.001 --backbone-lr 0.0003

# 不使用 ImageNet 预训练权重，从随机初始化开始训练
uv run python -m stage1_densenet121.train --no-pretrained --loss multi-label --lr 0.001

# 实时显示训练曲线
uv run python -m stage1_densenet121.train --plot-curves --loss multi-label --lr 0.001
```

启用 `--plot-curves` 后会打开一个 Matplotlib 窗口，每轮结束后更新三张图：
训练集/验证集 loss、整图准确率和单字符准确率。训练结束后关闭图表窗口，程序才会退出。

使用推荐的分层学习率时，一次本机参考实验达到 `99.21%`，即 381 张验证图片中
正确 378 张。该结果仅反映当前数据集，不代表其他验证码来源的识别率。

## 第二阶段：简单 CNN

第二阶段直接使用项目现有的 4 位验证码数据集，不下载 MNIST 或 CIFAR-10。模型支持通过
`--conv-blocks` 选择三或四个卷积块，并通过 `--bottleneck-channels` 在分类头前加入
`1×1` 卷积瓶颈。根据完整实验结果，第二阶段结项配置采用四卷积块、64 通道瓶颈和位置感知
共享分类头；代码保留面向初学者的中文注释，方便观察各层张量形状与结构优化过程。

先运行冒烟测试，确认数据、模型输出和反向传播正常：

```bash
uv run python -m stage2_simple_cnn.test_smoke
```

使用当前结项结构和训练策略复现 V1：

```bash
uv run python -m stage2_simple_cnn.train \
  --conv-blocks 4 \
  --bottleneck-channels 64 \
  --classifier-head position \
  --dropout 0 \
  --seed 2 \
  --epochs 40 \
  --batch-size 16 \
  --lr 0.001 \
  --augment \
  --evaluate-clean-train \
  --reduce-lr-on-plateau \
  --weight-decay 0.001 \
  --synthetic-train-dir data/synthetic_train \
  --synthetic-ratio 0.75 \
  --synthetic-validation-dir data/synthetic_validation
```

先按后文说明生成本地合成训练集和合成验证集，再运行该推荐命令。`--weight-decay` 大于 0 时训练器使用 AdamW；保持默认值 0 时继续使用历史 Adam 基线，
便于复现实验。多随机种子对照后，当前推荐的权重衰减系数为 `0.001`。`--dropout` 可在
`[0, 1)` 范围设置，设为 0 即关闭。标签平滑实验通过 `--label-smoothing 0.05` 启用；
默认值 0 保留原始交叉熵基线。当前位置分类头的多随机种子实验表明
`--reduce-lr-on-plateau` 可提高后期收敛精度，因此当前推荐启用。

`--evaluate-clean-train` 每轮会额外使用未增强训练图片并在 `model.eval()` 下计算干净训练集
指标，因此会增加训练时间。启用绘图时，训练曲线使用这组干净指标与验证曲线比较；终端仍会
同时保留开启增强和 Dropout 时的在线训练指标。

验证新增第三个卷积块时，保持数据增强和学习率调度关闭，只改变模型结构：

```bash
uv run python -m stage2_simple_cnn.train \
  --epochs 30 \
  --batch-size 16 \
  --lr 0.001
```

第三个卷积块把通道数从 `32` 增加到 `64`。随后只额外压缩特征图高度，使送入全连接层的
特征总数仍为 `8448`，避免因为全连接层参数量增加而干扰结构对比。

验证第四个卷积块时，保持三卷积块最佳配置中的数据增强和固定学习率不变：

```bash
uv run python -m stage2_simple_cnn.train \
  --conv-blocks 4 \
  --epochs 30 \
  --batch-size 16 \
  --lr 0.001 \
  --augment
```

第四个卷积块将通道数从 `64` 增加到 `128`，只沿高度方向继续池化。四卷积块结构送入
全连接层的特征数为 `128 × 3 × 22 = 8448`，与三卷积块结构的
`64 × 6 × 22 = 8448` 相同。这样新增参数只来自第四个卷积块，更适合进行深度消融比较。

压缩全连接层实验保持三卷积块和空间尺寸不变，在分类头前增加 `1×1` 卷积，将通道从
`64` 压缩到 `32`：

```bash
uv run python -m stage2_simple_cnn.train \
  --conv-blocks 3 \
  --bottleneck-channels 32 \
  --epochs 30 \
  --batch-size 16 \
  --lr 0.001 \
  --augment
```

瓶颈不会改变 `6×22` 的空间布局，全连接层输入从 `64 × 6 × 22 = 8448` 降为
`32 × 6 × 22 = 4224`。模型参数量从 `1,240,464` 降至 `634,352`，减少约 `48.9%`。
该结构实验达到 69.03% 整图准确率和 89.90% 单字符准确率，优于无瓶颈基线。

继续验证压缩边界时，将瓶颈通道从 `32` 降至 `16`，其他条件保持不变：

```bash
uv run python -m stage2_simple_cnn.train \
  --conv-blocks 3 \
  --bottleneck-channels 16 \
  --epochs 30 \
  --batch-size 16 \
  --lr 0.001 \
  --augment
```

16 通道结构的全连接层输入为 `16 × 6 × 22 = 2112`，模型参数量为 `329,152`，
相比无瓶颈基线减少约 `73.5%`。该结构达到 73.23% 整图准确率和 91.14% 单字符准确率，
是三卷积块实验中的最佳精度配置。

最后将瓶颈从 `16` 通道降至 `8`，确定继续压缩分类头时的性能边界：

```bash
uv run python -m stage2_simple_cnn.train \
  --conv-blocks 3 \
  --bottleneck-channels 8 \
  --epochs 30 \
  --batch-size 16 \
  --lr 0.001 \
  --augment
```

8 通道结构的全连接层输入为 `8 × 6 × 22 = 1056`，模型参数量为 `176,552`，相比无瓶颈
基线减少约 `85.8%`，单次实验达到 72.97% 整图准确率和 91.08% 单字符准确率。

训练时实时显示 loss、整图准确率和单字符准确率曲线：

```bash
uv run python -m stage2_simple_cnn.train --epochs 10 --batch-size 16 --lr 0.001 --plot-curves
```

对训练集启用轻量仿射增强（验证集不增强）：

```bash
uv run python -m stage2_simple_cnn.train --epochs 30 --batch-size 16 --lr 0.001 --augment
```

`--augment` 会随机执行不超过 `3°` 的旋转、轻微平移、`0.95~1.05` 倍缩放和小幅错切；
不会执行会破坏验证码字符顺序的翻转或大幅裁剪。

`--color-jitter` 只作用于训练集，随机执行幅度为 `0.15` 的亮度、对比度和饱和度变化，
以及幅度为 `0.02` 的轻量色相变化；多随机种子实验表明它会降低当前模型的平均准确率，
因此默认关闭。

合成混合训练引入前，使用位置感知共享分类头建立纯真实数据结构基线，并将瓶颈通道设为 64：

```bash
uv run python -m stage2_simple_cnn.train \
  --conv-blocks 4 \
  --bottleneck-channels 64 \
  --classifier-head position \
  --dropout 0 \
  --seed 0 \
  --epochs 40 \
  --batch-size 16 \
  --lr 0.001 \
  --augment \
  --evaluate-clean-train \
  --reduce-lr-on-plateau \
  --weight-decay 0.001
```

`position` 分类头把宽度为 22 的特征图等分成 4 个字符区域，分别在空间维度求平均，再让
四个位置共享同一个 `64→36` 线性分类器。输出形状仍为 `[B, 4, 36]`。该配置参数量为
108,644，比 175,144 参数的 `flatten` 基线减少约 38.0%，同时把瓶颈从 8 通道提高到
64 通道。实现使用等宽分段均值而不是 `AdaptiveAvgPool2d((1, 4))`，以兼容 MPS 对非整除
自适应池化的限制。当前推荐不启用 `--color-jitter` 或 `--label-smoothing`。

比较位置分类头的 16、32、64 通道时，可以同时开启干净训练集评估：

```bash
for channels in 16 32 64; do
  for seed in 0 1 2; do
    uv run python -m stage2_simple_cnn.train \
      --conv-blocks 4 \
      --bottleneck-channels "$channels" \
      --classifier-head position \
      --dropout 0.1 \
      --seed "$seed" \
      --epochs 30 \
      --batch-size 16 \
      --lr 0.001 \
      --augment \
      --evaluate-clean-train \
      --weight-decay 0.001
  done
done
```

这组实验一次只比较瓶颈通道数。若之后单独比较 Dropout，可使用 `--dropout 0` 关闭或传入
其他 `[0, 1)` 范围内的概率，不应与瓶颈通道实验同时改变。

根据验证 loss 自动降低学习率：

```bash
uv run python -m stage2_simple_cnn.train \
  --epochs 30 \
  --batch-size 16 \
  --lr 0.001 \
  --reduce-lr-on-plateau
```

启用 `--reduce-lr-on-plateau` 后，如果验证 loss 连续多轮没有改善，学习率会降低为原来的
`30%`，最低降至 `0.00001`。它没有提升早期三卷积块模型，但后续位置感知分类头的多 seed
实验确认它能够改善当前推荐结构，因此当前推荐训练命令启用该调度器。

第二阶段的共用参数默认值为：`--epochs 10`、`--batch-size 16`、`--lr 0.001`，
`--plot-curves` 默认关闭。第二阶段额外支持 `--bottleneck-channels`、`--classifier-head`、
`--dropout`、`--seed`、`--weight-decay`、`--label-smoothing`、`--color-jitter`、
`--evaluate-clean-train`、`--train-dir`、`--validation-dir`、`--synthetic-train-dir`、
`--synthetic-ratio` 和 `--synthetic-validation-dir`。分类头默认使用 `flatten`，Dropout 默认是
`0.1`，随机种子默认是 `0`，权重衰减、标签平滑和合成比例默认都是 `0`，颜色增强、干净训练
评估和合成验证默认关闭。权重衰减为 0 时
使用 Adam 以复现历史基线，大于 0 时使用 AdamW。启用曲线后，每轮结束都会刷新训练集和
验证集曲线；训练结束后，关闭 Matplotlib 窗口程序才会退出。

这是用于学习和结构对比的项目，第二阶段默认只使用统一权重文件
`stage2_simple_cnn/checkpoints/model.pth`。不同卷积块、瓶颈通道和 seed 的训练会直接覆盖
该文件，不为每组参数长期保留独立 `.pth`；实验结论以日志和 README 记录为准。只有明确
需要保留某次权重时才传入 `--model-path`。权重选择首先比较验证集整图准确率；整图准确率
相同时保存验证 loss 更低的轮次。模型输入形状为 `[B, 3, 100, 180]`，输出形状为
`[B, 4, 36]`。其中 `B` 是批量大小，
`4` 是字符位置，`36` 是每个位置的候选字符数量。训练和验证都会同时输出整图准确率与
单字符准确率。

## 独立测试集与混淆矩阵

`data/test` 已经反复用于模型结构、训练策略和最佳轮次选择，因此它是验证集，不能继续作为
最终测试集。项目为真正未见过的数据预留本地目录 `data/independent_test`；该目录和评估报告
默认不提交到 Git，避免后续训练过程无意中使用独立测试图片。

优先将真实采集且从未参与训练、模型选择或人工调参的图片放入该目录。文件名必须是 4 位真实
标签，例如 `2n6m.png`。真实图片应来自独立采集批次，并覆盖不同字体、颜色、干扰线、背景和
字符粘连情况；不要从现有 `data/train` 或 `data/test` 复制或变换图片来充当独立测试数据。

没有新的真实图片时，可使用项目提供的合成生成器创建固定测试集：

```bash
uv run python -m stage2_simple_cnn.generate_captchas \
  --count 400 \
  --seed 20250310
```

生成器默认输出 400 张 `180×100` 四位验证码，使用数据中实际出现的 20 个字符，并让每个位置的
字符分布保持均衡。图片随机组合常见拉丁字体、灰白背景、颜色、阴影、旋转、伸缩、干扰线、
彩色网格、噪点和轻微模糊。`manifest.json` 会记录随机种子、字体、每张图片的样式参数和
SHA-256，可用于确认测试集没有被改写。目标目录已有图片时生成器默认拒绝覆盖；只有明确重建时
才使用 `--replace-existing`。

合成测试集主要衡量模型面对独立字体和渲染扰动时的迁移能力，不能替代同一业务来源的真实新
数据。生成参数确认后应冻结该批图片，不能根据测试结果反复修改生成器或模型。

使用当前推荐模型结构执行一次最终评估：

```bash
uv run python -m stage2_simple_cnn.evaluate
```

评估器会先使用 SHA-256 检查独立测试图片是否与 `data/train`、`data/test` 存在完全相同的
文件；发现历史目录或重复图片时默认拒绝继续。评估成功后生成：

| 文件 | 内容 |
| --- | --- |
| `stage2_simple_cnn/evaluation_reports/metrics.json` | 整图、单字符、各位置准确率及重复检查结果 |
| `stage2_simple_cnn/evaluation_reports/confusion_matrix.csv` | 完整 36 类字符混淆矩阵 |
| `stage2_simple_cnn/evaluation_reports/confusion_matrix.png` | 仅显示实际出现类别的可视化混淆矩阵 |
| `stage2_simple_cnn/evaluation_reports/errors.csv` | 每张错误图片、真实值、预测值、错误位置和置信度 |

若只是验证评估脚本或复查历史验证集，可以显式运行：

```bash
uv run python -m stage2_simple_cnn.evaluate \
  --data-dir data/test \
  --allow-known-data \
  --output-dir stage2_simple_cnn/evaluation_reports/validation
```

该命令会输出醒目警告，其结果仍然是验证指标，不是独立测试准确率。独立测试原则上只在模型、
训练参数和停止规则全部锁定后执行一次；如果根据独立测试集错误继续调整模型，这组数据就已经
转化为新的验证集，需要另行收集下一组独立测试数据。

独立测试图片和生成清单默认只保留在本地，不提交仓库。默认自动扫描系统中的常见拉丁字体，
因此相同 seed 只保证在字体集合不变的环境中复现；跨机器严格复现时，应通过可重复的
`--font-path` 显式指定同一组字体文件。

75% 合成比例的结构、训练参数和停止规则锁定后，本机使用 seed `20250310` 生成并冻结了最终
独立测试集：400 张、每个字符在每个位置各出现 20 次，与 `data/train`、`data/test`、
`data/synthetic_train` 和 `data/synthetic_validation` 的 SHA-256 重复数均为 0。使用循环训练后
保留的 Seed 2 当前权重执行一次最终评估，结果为：

| 指标 | 最终独立测试结果 |
| --- | ---: |
| 整图准确率 | **383 / 400，95.75%** |
| 单字符准确率 | **1583 / 1600，98.94%** |
| 第 1～4 位准确率 | 98.75%、98.75%、99.25%、99.00% |
| 整图错误数 | 17 |

最多的字符混淆为 `n→m` 3 次，其余列出的单类混淆均只有 1 次。这批 seed `20250310` 数据及其
结果现已锁定；不能再根据这 17 张错误图片调整模型、训练参数或生成器，否则它将失去最终测试集
资格。该指标衡量同一生成器家族下的新 seed 与新渲染组合，仍不能替代真实业务来源的新采集数据。

本机此前使用 400 张、seed `20250308` 的合成数据进行迁移测试，每个字符在每个位置各出现 20 次，
与历史训练/验证图片的 SHA-256 重复数为 0。首次生成时发现 `SFGeorgianRounded.ttf` 被名称中的
`Georgia` 误判为常规拉丁字体，缺失字符被画成多条横向占位符，人眼无法辨认。生成器现已同时
按字体名称排除非拉丁字体，并要求目标字符的字形掩码全部不同；训练集和验证集均已重新生成。
修复后、引入混合训练之前的统一权重合成验证基线为：

| 指标 | 结果 |
| --- | ---: |
| 整图准确率 | 55 / 400，13.75% |
| 单字符准确率 | 825 / 1600，51.56% |
| 第 1～4 位准确率 | 51.25%、47.75%、53.25%、54.00% |

该结果仍远低于历史验证集的 97.38%，说明模型明显依赖原始验证码来源中的字体和渲染分布，对独立

## 混合真实与合成数据训练

真实训练图片；合成池按需随机抽样，避免 4000 张合成图片完全压过真实数据。默认值仍为 0，未传
合成参数时会复现原来的纯真实数据训练流程。

Seed 0 的比例实验结果如下；合成指标取原始验证集最佳权重所在轮次：

| Seed | 最佳轮次 | 原始验证整图 | 原始单字符 | 合成验证整图 | 合成单字符 |

| 样本标准差 | — | **0.15** | **0.03** | **0.90** | **0.24** |

三 seed 的原始验证整图准确率范围只有 0.26 个百分点，说明结果稳定。平均干净训练整图准确率为

**75% 合成比例**作为推荐方案，即每个 batch 固定使用 4 张真实图片和 12 张合成图片：

```bash
uv run python -m stage2_simple_cnn.train \
  --conv-blocks 4 \
  --bottleneck-channels 64 \
  --classifier-head position \
  --dropout 0 \

  --epochs 40 \
  --batch-size 16 \
  --lr 0.001 \
  --augment \
  --evaluate-clean-train \
  --reduce-lr-on-plateau \
  --weight-decay 0.001 \
  --synthetic-train-dir data/synthetic_train \
  --synthetic-ratio 0.75 \
  --synthetic-validation-dir data/synthetic_validation
```

训练过程每轮同时输出原始验证集和合成验证集指标，但学习率调度、最佳轮次选择和权重保存仍然只
依据原始验证集。三个 seed 用于验证配置稳定性，不把 seed 本身作为继续挑选最高分的超参数；V1
按用户确认冻结循环训练后保留并完成最终测试的 Seed 2 权重。由于 75% 每轮有 200 个 batch，
计算量分别约为 50% 和 25% 配置的 2 倍和 3 倍，
该收益包含更多合成样本和更多优化步骤的共同作用，不应解释为纯粹的比例消融结果。

## 已知限制

- 只能识别固定 4 个字符。
- 分类层保留 `0-9a-z` 共 36 个输出，但当前训练和测试数据只覆盖实际出现的
  `2345678abcdefgmnpwxy` 共 20 个字符；95.75% 最终测试准确率不代表其余 16 类已被验证。
- 标签必须来自图片文件名。
- 合成生成器不能替代同一业务来源的新真实验证码，最终上线指标仍需真实独立数据验证。
- GUI 每次识别都会重新加载模型，适合演示，不适合高吞吐服务。
- 第二阶段输入只执行 `ToTensor()`，尚未评估基于当前数据集统计量的归一化；ImageNet mean/std
  不一定适合从零训练的 Simple CNN。
- 仅应在自有或明确授权的验证码系统中使用。

### 四卷积块多随机种子复验

固定四卷积块、轻量仿射数据增强、固定学习率 `0.001` 和 30 轮训练，分别使用 seed
`0`、`1`、`2` 比较 8/16 通道瓶颈：

| 瓶颈通道 | Seed 0 | Seed 1 | Seed 2 | 平均整图准确率 | 样本标准差 | 参数量 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 16 | 79.53% | 80.05% | 77.69% | 79.09% | 1.24 | 252,224 |
| **8** | **80.58%** | 78.48% | **79.00%** | **79.35%** | **1.09** | **175,144** |

8 通道的平均整图准确率高 0.26 个百分点，波动略小，同时参数量比 16 通道少 30.6%。
精度差异很小，但 8 通道在平均准确率、稳定性和模型规模上均不劣，因此选为推荐配置。

### AdamW 权重衰减实验

固定四卷积块、8 通道瓶颈、轻量仿射数据增强、学习率 `0.001` 和 30 轮训练，只改变
优化器及权重衰减系数。`weight_decay=0` 使用历史 Adam 基线，大于 0 时使用 AdamW：

| 权重衰减 | Seed 0 | Seed 1 | Seed 2 | 平均整图准确率 | 样本标准差 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0（Adam） | 80.58% | 78.48% | 79.00% | 79.35% | **1.09** |
| `1e-4` | **81.89%** | 77.69% | 79.53% | 79.70% | 2.11 |
| `3e-4` | 81.10% | 77.95% | 79.00% | 79.35% | 1.60 |
| **`1e-3`** | 81.63% | **78.48%** | **82.15%** | **80.75%** | 1.99 |

`1e-4` 只将平均准确率提高 0.35 个百分点且波动增大，`3e-4` 与 Adam 基线平均值相同；
`1e-3` 在三个 seed 上分别提升 1.05、0 和 3.15 个百分点，平均提高 1.40 个百分点，约等于
每轮多正确识别 5.3 张验证图片，因此选为当前推荐权重衰减。它的随机种子波动仍高于 Adam
基线，后续实验仍应比较多 seed 平均值，不能只使用 82.15% 的单次最高值。

在 `1e-3` 三次实验的最佳验证轮次，训练整图准确率分别为 98.62%、97.50% 和 98.12%，
与验证准确率仍相差约 16～19 个百分点，说明 AdamW 带来了小幅泛化收益，但没有消除过拟合。

### Label smoothing 实验

固定 AdamW 权重衰减 `1e-3` 及其余推荐条件，只将交叉熵的标签平滑系数从 0 调整为
`0.05`：

| 标签平滑 | Seed 0 | Seed 1 | Seed 2 | 平均整图准确率 | 样本标准差 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 81.63% | 78.48% | **82.15%** | 80.75% | 1.99 |
| `0.05` | **82.94%** | **80.58%** | 79.79% | **81.10%** | **1.64** |

标签平滑在 Seed 0、1 上分别提升 1.31 和 2.10 个百分点，但 Seed 2 下降 2.36 个百分点；
三 seed 平均只提高 0.35 个百分点，约等于多正确 1.3 张验证图片。样本标准差从 1.99 降至
1.64，但平均提升低于预先设定的约 1 个百分点保留门槛，因此目前不把 `0.05` 加入推荐配置。
标签平滑损失包含固定的平滑惩罚项，新旧实验的 loss 绝对值不能直接比较，应以准确率为主。

三个最佳验证轮次的训练整图准确率仍为 98.88%、98.38% 和 98.38%，平均训练—验证差距
约 17.44 个百分点，说明 `0.05` 没有明显缓解过拟合。

### ColorJitter 实验

固定 AdamW 权重衰减 `1e-3` 及其余推荐条件，在轻量仿射增强后增加 ColorJitter：

| 颜色增强 | Seed 0 | Seed 1 | Seed 2 | 平均整图准确率 | 样本标准差 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 关闭 | **81.63%** | **78.48%** | **82.15%** | **80.75%** | 1.99 |
| ColorJitter | 80.31% | 78.22% | 79.53% | 79.35% | **1.06** |

ColorJitter 在三个 seed 上分别下降 1.32、0.26 和 2.62 个百分点，平均下降 1.40 个
百分点。虽然样本标准差下降，但模型只是更稳定地收敛到较低准确率，因此不加入推荐配置。
三个最佳验证轮次的训练整图准确率分别为 95.62%、96.25% 和 97.50%，平均训练—验证差距
约 17.10 个百分点，与关闭颜色增强时约 17.33 个百分点基本相同，也没有明显缓解过拟合。

### 位置感知共享分类头实验

固定四卷积块、AdamW 权重衰减 `1e-3`、轻量仿射增强和其他训练条件，将 8 通道展平
分类头替换为 32 通道位置感知共享分类头：

| 分类头 | 参数量 | Seed 0 | Seed 1 | Seed 2 | 平均整图准确率 | 样本标准差 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Flatten + 瓶颈 8 | 175,144 | 81.63% | 78.48% | 82.15% | 80.75% | 1.99 |
| **Position + 瓶颈 32** | **103,300** | **93.70%** | **91.08%** | **92.91%** | **92.56%** | **1.34** |

位置感知分类头在三个 seed 上分别提升 12.07、12.60 和 10.76 个百分点，平均提升 11.81 个
百分点，相当于平均多正确识别约 45 张验证图片。模型参数量同时减少 41.0%，随机种子样本
标准差从 1.99 降到 1.34，因此它在精度、规模和稳定性三方面均明显优于展平分类头。

训练阶段显示的准确率来自开启 Dropout 且经过随机仿射增强的当前训练批次，而验证准确率来自
`model.eval()` 下的未增强图片，两者不是同条件测量。位置分类头出现验证准确率高于训练准确率
是合理现象，不能据此判断数据泄漏或欠拟合。现在可以通过 `--evaluate-clean-train` 每轮增加
关闭增强和 Dropout 的干净训练集评估指标，再与验证集进行同条件比较。

### 位置分类头瓶颈通道实验

保持位置分类头、Dropout `0.1`、AdamW 权重衰减 `1e-3` 和轻量仿射增强不变，只比较
16、32、64 个瓶颈通道。表中的干净训练准确率取各次最高验证准确率所在轮次：

| 瓶颈通道 | Seed 0 | Seed 1 | Seed 2 | 验证均值 | 样本标准差 | 干净训练均值 | 平均泛化差距 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 16 | 88.98% | 92.91% | 87.93% | 89.94% | 2.63 | 93.08% | 3.14 |
| 32 | 95.28% | 93.44% | 日志缺失 | 94.36%（2 seeds） | 1.30（2 seeds） | 96.50% | 2.14 |
| **64** | **95.28%** | **94.23%** | **93.96%** | **94.49%** | **0.70** | **97.87%** | 3.38 |

16 通道的表达能力明显不足。64 通道三次实验均超过 93.9%，平均达到 94.49%，而且波动最小；
32 通道现有两次实验平均为 94.36%，与 64 通道只差 0.13 个百分点，但缺少 Seed 2，暂时无法
进行完整的三 seed 公平比较。因此当前把 64 通道作为**暂定推荐配置**，主要依据是它具有完整且
稳定的三 seed 结果，而不是 0.13 个百分点这一不足以证明优势的均值差异。

64 通道最佳验证轮次的干净训练—验证差距分别为 2.72、3.27 和 4.16 个百分点，平均 3.38 个
百分点。与早期展平分类头约 17 个百分点的差距相比，过拟合已大幅缓解，但仍有轻度泛化差距。

### 64 通道 Dropout 实验

固定 64 通道位置分类头及其他训练条件，只改变分类头 Dropout。表中的干净训练准确率取各次
最高验证准确率所在轮次：

| Dropout | Seed 0 | Seed 1 | Seed 2 | 验证均值 | 样本标准差 | 干净训练均值 | 平均泛化差距 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| **0** | **96.85%** | 93.70% | **94.75%** | **95.10%** | 1.60 | **98.33%** | **3.23** |
| `0.05` | 93.96% | **96.33%** | 93.96% | 94.75% | 1.37 | 98.29% | 3.54 |
| `0.1` | 95.28% | 94.23% | 93.96% | 94.49% | **0.70** | 97.87% | 3.38 |
| `0.2` | 95.80% | 91.60% | 92.13% | 93.18% | 2.29 | 96.50% | 3.32 |

`0.05` 的平均准确率为 94.75%，介于关闭 Dropout 和 `0.1` 之间；样本标准差 1.37，只比关闭
Dropout 的 1.60 小 0.23，未同时取得更高均值或接近 `0.1` 的稳定性。`0.2` 平均下降到
93.18%，说明增强 Dropout 会造成正则化过强。四组平均泛化差距都约为 3.2～3.5 个百分点，
Dropout 并没有实质缩小剩余差距。

如果优先考虑三 seed 平均准确率，关闭 Dropout 的 95.10% 是当前最佳；如果优先考虑不同 seed
下的稳定性，`0.1` 的标准差 0.70 更好。本项目当前目标是在固定样本量下逐步提高平均准确率，
因此将推荐值调整为 `0`，同时明确它相对 `0.1` 的平均提升只有 0.61 个百分点，证据强度有限。

### 训练轮数实验

关闭 Dropout 的三次 30 轮实验最佳结果都出现在第 28～30 轮，因此只将训练轮数增加到 40：

| 训练轮数 | Seed 0 | Seed 1 | Seed 2 | 验证均值 | 样本标准差 | 干净训练均值 | 平均泛化差距 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 30 | **96.85%** | 93.70% | 94.75% | 95.10% | 1.60 | **98.33%** | 3.23 |
| **40** | **96.85%** | **95.54%** | **95.01%** | **95.80%** | **0.95** | 98.29% | **2.49** |

40 轮在 Seed 0 上没有超过第 30 轮的结果，但 Seed 1 和 Seed 2 分别提升 1.84 和 0.26 个
百分点；三 seed 平均提高 0.70 个百分点，样本标准差从 1.60 降到 0.95，平均泛化差距也从
3.23 降到 2.49 个百分点。虽然平均提升不足 1 个百分点，但精度、稳定性和泛化差距均改善，
因此将推荐训练轮数更新为 40。

### 当前位置分类头学习率调度实验

保持 40 轮和其他条件不变，只启用 `ReduceLROnPlateau`：

| 学习率策略 | Seed 0 | Seed 1 | Seed 2 | 验证均值 | 样本标准差 | 干净训练均值 | 平均泛化差距 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 固定 `0.001` | **96.85%** | 95.54% | 95.01% | 95.80% | 0.95 | 98.29% | 2.49 |
| **ReduceLROnPlateau** | **96.85%** | **97.38%** | **97.38%** | **97.20%** | **0.31** | **99.46%** | **2.26** |

调度器分别在 Seed 0、1、2 的第 38、32、33 轮后把学习率从 `0.001` 降到 `0.0003`。
Seed 0 的历史最佳仍是第 30 轮的 96.85%，因此结果不变；Seed 1 和 Seed 2 分别提高 1.84 和
2.37 个百分点。三 seed 平均提高 1.40 个百分点，样本标准差从 0.95 降到 0.31，平均泛化
差距也从 2.49 降到 2.26 个百分点，因此在当前位置分类头上明确保留该调度器。

### 调度器下的训练轮数复验

保持调度器及其他条件不变，把训练轮数从 40 增加到 50：

| 训练轮数 | Seed 0 | Seed 1 | Seed 2 | 验证均值 | 样本标准差 | 干净训练均值 | 平均泛化差距 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| **40** | 96.85% | 97.38% | **97.38%** | 97.20% | 0.31 | 99.46% | **2.26** |
| 50 | **97.11%** | **97.64%** | **97.38%** | **97.38%** | **0.27** | 100.00% | 2.62 |

50 轮在 Seed 0 和 Seed 1 上各提高 0.26 个百分点，Seed 2 不变；三 seed 平均只提高 0.18 个
百分点，约等于平均多正确 0.7 张验证图片，未达到保留门槛。与此同时，最佳轮次的干净训练集
已经全部达到 100%，平均泛化差距反而从 2.26 增到 2.62 个百分点，且训练计算量增加 25%。
因此不保留 50 轮，当前推荐仍为 40 轮并启用调度器。

50 轮最佳验证轮次分别为第 47、50、40 轮。虽然个别 seed 在后十轮仍有小幅提升，但整体收益
已经接近验证集单张图片造成的离散波动，因此后续没有继续增加轮数或盲目微调 Dropout，而是转向
独立评估和合成数据鲁棒性实验。最终测试现已锁定，不再根据其中的错误样本继续调整模型。

早期三卷积块实验中该调度器没有收益，但当前位置分类头的结果已经证明，旧结构上的结论不能
直接套用于新结构。

实验结论：

- 原模型约 99.9% 的参数集中在全连接层，增加一次温和的 `2×2` 平均池化后，模型参数量
  从约 519 万降至约 122 万，减少约 76.5%，同时整图准确率有所提升。
- 将特征图直接压缩至 `5×15` 会丢失过多字符空间信息，整图准确率明显下降，因此不采用。
- `Dropout(0.3)` 对当前小型 CNN 正则化过强；`Dropout(0.1)` 能提供小幅提升。
- 两个卷积层采用 `Conv2d → BatchNorm2d → ReLU → MaxPool2d` 后，收敛速度和验证指标
  均有明显改善；其中 BatchNorm 与 Dropout(0.1) 同时使用时达到 45.93% 整图准确率。
- 增加第三个 `32 → 64` 卷积块后，固定学习率实验达到 57.74%，比两卷积块基线提升
  11.81 个百分点，对应 381 张验证图片中多识别正确 45 张。第三个卷积块显著增强了对字符
  笔画、轮廓和干扰线组合特征的提取能力。
- 早期三卷积块结构使用 `ReduceLROnPlateau` 时达到 57.48%，比固定学习率少正确 1 张，
  因而当时未采用；该结论只适用于旧结构。
- 三卷积块配合轻量仿射数据增强后，第 27 轮同时取得最低验证 loss `0.4360`、最高整图
  准确率 67.72% 和最高单字符准确率 89.24%。相比不增强的三卷积块多识别正确 38 张，
  相比两卷积块基线总计提升 21.79 个百分点。
- 四卷积块不使用瓶颈时达到 66.93% 整图准确率和 88.71% 单字符准确率，增加网络深度
  但保留大型全连接层没有带来提升。
- 三卷积块的 `64→32`、`64→16` 和 `64→8` 通道瓶颈分别达到 69.03%、73.23% 和
  72.97% 整图准确率，证明压缩分类头能够改善泛化，但三卷积块在 8 通道时已接近边界。
- 四卷积块多 seed 复验中，16 通道和 8 通道的平均整图准确率分别为 79.09% 和 79.35%；
  8 通道样本标准差更低，并以 175,144 个参数比 16 通道减少约 30.6%，因此综合胜出。
- AdamW 权重衰减实验中，`1e-3` 将三 seed 平均整图准确率从 79.35% 提高到 80.75%，
  单次最高达到 82.15%；`1e-4` 和 `3e-4` 的平均提升不足，因此不采用。
- Label smoothing `0.05` 的三 seed 平均准确率为 81.10%，只比无标签平滑提高 0.35 个
  百分点，未达到保留门槛；保留命令行能力用于复验，但当前推荐值仍为 0。
- ColorJitter 将三 seed 平均准确率从 80.75% 降到 79.35%，且几乎没有缩小训练—验证差距，
  因此只保留命令行能力，不加入推荐配置。
- 32 通道位置感知共享分类头首次将三 seed 平均准确率从 80.75% 提高到 92.56%，参数量从
  175,144 降到 103,300，是当前最明显的一次结构提升。
- 后续通道实验中，16 通道平均准确率只有 89.94%；64 通道完整三 seed 平均达到 94.49%，
  样本标准差为 0.70。32 通道目前只有两个可用 seed，平均为 94.36%，因此暂不能证明 64
  通道在平均准确率上显著胜出，但 64 通道具有更完整、稳定的现有证据。
- 64 通道 Dropout 实验中，关闭 Dropout 的平均准确率最高，为 95.10%；`0.05`、`0.1` 和
  `0.2` 分别为 94.75%、94.49% 和 93.18%。Dropout 没有缩小约 3.3 个百分点的泛化差距，
  且强度越高平均准确率总体越低，因此按当前精度优先目标关闭 Dropout。
- 将训练从 30 轮增加到 40 轮后，平均准确率从 95.10% 提高到 95.80%，标准差从 1.60 降到
  0.95，平均泛化差距从 3.23 降到 2.49 个百分点，因此保留 40 轮训练。
- 在 40 轮新基线上启用 `ReduceLROnPlateau` 后，平均准确率进一步提高到 97.20%，标准差降到
  0.31，平均泛化差距降到 2.26 个百分点，因此新结构明确保留学习率调度。
- 调度器下增加到 50 轮只将平均准确率提高到 97.38%，增幅 0.18 个百分点，同时干净训练集
  达到 100%、泛化差距增至 2.62 个百分点且计算量增加 25%，因此不保留 50 轮。
- 75% 合成训练比例在 Seed 0、1、2 上的原始验证整图准确率分别为 96.59%、96.59% 和
  96.33%，平均 96.50%、样本标准差 0.15；对应合成验证平均整图准确率为 96.25%、样本标准差
  0.90。相比纯真实训练的 97.20% 原始验证平均值下降 0.70 个百分点，但显著改善合成鲁棒性。
- 当前推荐配置为四卷积块、`128→64` 通道瓶颈、位置感知共享分类头、关闭 Dropout、40 轮、
  初始学习率 `0.001`、`ReduceLROnPlateau`、AdamW 权重衰减 `1e-3`、轻量仿射数据增强和
  75% 合成训练比例；不启用 ColorJitter 或 Label smoothing。当前 V1 冻结权重使用 Seed 2。
- 本项目以学习和实验记录为主，训练默认覆盖 `stage2_simple_cnn/checkpoints/model.pth`，
  不按卷积块、瓶颈通道或 seed 长期保留独立权重，也不提交训练生成的 `.pth` 文件。

上述指标来自反复参与模型选择的 `data/test`，因此属于验证结果，不是独立测试集上的最终
识别率。

## 第二阶段结项总结

### 结项判断

第二阶段以“从零构建一个可解释、可复验并具备基本跨渲染泛化能力的轻量 CNN”为学习目标，现已
完成。项目不再围绕当前验证集和最终测试集继续追求零点几个百分点的微调；后续工作如继续开展，
应转向真实业务数据、推理工程、模型导出或置信度校准，并建立新的独立测试集评价新版本。

### 最终方案

| 项目 | 结项配置 |
| --- | --- |
| 网络 | 四卷积块 Simple CNN |
| 瓶颈 | `128→64` 的 `1×1` 卷积 |
| 分类头 | 位置感知、四位置共享的 `64→36` 分类器 |
| 参数量 | 108,644 |
| 输入/输出 | `[B, 3, 100, 180]` → `[B, 4, 36]` |
| 优化器 | AdamW，weight decay `0.001` |
| 训练策略 | 40 轮、初始学习率 `0.001`、`ReduceLROnPlateau` |
| 正则与增强 | Dropout 0、轻量仿射增强、不使用 ColorJitter 或 Label smoothing |
| 数据组成 | batch size 16，每批 4 张真实图片和 12 张合成图片 |
| V1 冻结 Seed | Seed 2；Seed 0、1、2 只用于验证配置稳定性 |

| 数据集 | 整图准确率 | 单字符准确率 | 说明 |

“整图准确率”要求一张图片的 4 个位置全部预测正确；“单字符准确率”按全部图片的正确位置数计算。
以上测试只覆盖实际数据中的 20 个字符，而不是分类层保留的完整 36 类。

最终测试使用 seed `20250310` 的 400 张冻结图片。除评估器默认检查 `data/train` 和 `data/test`
外，生成后还单独审计了 `data/synthetic_train` 和 `data/synthetic_validation`，与四个已知目录的
SHA-256 重复数均为 0。审计结果保存在本地 `data/independent_test/final_audit.json`。

冻结权重 SHA-256 为 `f604e560ab150152cb51ef71a5e7572124c6f6e8caca0705f1f16b7175e941cb`，最终测试
`manifest.json` SHA-256 为 `010e452f00cd5f176a2296d72b6917b4479621a5b7d835c2985a85a3b45ac8f1`。
该结果属于当前 V1 模型，不再用于后续调参。由于最终集仍来自同一生成器家族，它证明了新图片与
新渲染组合下的稳定性，但不能替代真实业务来源的新采集测试数据。自动字体发现还依赖本机字体池；
跨机器严格复现时必须显式提供相同的 `--font-path`。

### 主要学习结论

1. 原始模型的大型全连接层是主要参数和过拟合来源；位置感知共享分类头把参数量压缩到 108,644，
   同时显著提升验证准确率。
2. 模型深度、瓶颈通道、正则化和训练轮数需要通过控制变量与多 Seed 实验判断，单次最高值不足以
   支撑结构选择。
3. `ReduceLROnPlateau` 对早期结构没有收益，但在最终位置感知结构上明显改善后期收敛，说明训练
   策略结论不能脱离具体模型结构复用。
4. 纯真实训练在原始验证集表现较好，却在独立渲染上存在严重域偏移；固定批次比例混合合成数据后，
   原始与合成验证准确率均稳定在约 96%。
5. 75% 合成比例的收益包含更多合成样本和更多优化步骤，并非严格控制计算量的纯比例消融结果。
6. 验证集、合成鲁棒性验证集和最终测试集必须分工明确；测试集一旦影响训练决策，就不再是最终
   测试集。

## 第三阶段：CNN + CTC 可变长度识别

第三阶段以第二阶段四卷积块 CNN 为特征提取基础，从随机初始化开始学习 2～6 位可变长度字符识别。
第一版保持输入画布为 `100×180`，使用字符表 `2345678abcdefgmnpwxy`，暂不加入 LSTM。
模型保留 CNN 输出的 22 列横向特征作为时间步，经高度平均和共享线性分类器后输出
`[B, 22, 21]`；21 类包含 20 个字符和一个 CTC blank。

### 极小数据集过拟合诊断

首次链路诊断使用 10 张内存生成的固定干净图片，覆盖 2～6 位长度，并包含 `aa`、`33`、`xx`
等连续重复字符。训练使用 batch size 10、Adam、学习率 `0.003`、seed 0 和 MPS，不保存诊断
checkpoint。模型从随机初始化训练，在第 109 轮达到 100% 训练集整串准确率，loss 从第 1 轮的
15.3197 降至 0.0804；10 条标签均被贪心 CTC 解码正确。

该结果只证明图片加载、CNN 序列输出、可变长度标签编码、CTC loss、反向传播和贪心解码已经形成
可工作的训练闭环，不代表模型对未见图片具有泛化能力。

### 正式合成数据 V1

正式数据使用 seed `20250311` 和中等难度动态布局生成器，输入画布为 `100×180`。训练集、验证集和
测试集分别包含 1,500、250 和 250 张图片；2～6 位每种长度分别占 300、50 和 50 张。三个集合从
全局唯一标签中按长度分层切分，因此标签交集为 0；生成后的 SHA-256 审计也确认图片内容交集为 0。
本地数据及每个集合的 `manifest.json` 位于 `data/stage3_variable_length/`，不提交 Git。正式 Dataset
以 manifest 作为标签和图片身份来源，而不依赖文件名解析。

### 正式基线验证错误分析

第 31 轮最佳 checkpoint 在 250 张验证图片上产生 35 条错误字符串和 43 次最短编辑操作，其中
27 条错误只差 1 次编辑，另外 8 条差 2 次编辑。字符级操作包括 24 次替换、16 次删除和 3 次插入；
按整条字符串的主要类型统计为 17 条纯替换、10 条纯删除、3 条纯插入和 5 条混合错误。因此当前问题以
视觉替换和漏字符为主，额外插入不是主要矛盾。

六位样本贡献 15/35 的错误字符串、21/43 的编辑距离和 11/16 的删除操作，说明六位布局中的小字符、
拥挤或干扰更容易造成漏识别。连续重复字符样本为 34/39 正确（87.18%），略高于非重复样本的
181/211（85.78%），因此 CTC 连续重复折叠不是整体瓶颈。替换错误集中在 `m↔n`（7 次）、`8↔g`
（4 次）、`d↔a`（3 次）和 `n→w`（2 次）；这些组合占 24 次替换中的 16 次。代表图片还显示交叉
干扰线会遮挡 `8`，六位低对比度小字符容易混淆，而 `4fwfaf` 的首部字符和干扰线交叠时发生连续删除。
下一次控制变量实验应优先提高训练渲染多样性并针对六位布局，而不是继续增加训练轮数；是否加入序列模型
应在数据侧实验后再决定。

计划使用 `3,000 × 20 = 60,000` 次样本呈现；其余模型结构、Adam、学习率 `0.001`、batch size 16、
seed 0、验证集和贪心解码保持一致。该实验主要检验增加同标签视觉版本能否降低 `m/n`、`8/g` 等替换和
六位漏字符，而不是检验更长训练时间。正式 V2 数据已按计划生成：2～6 位每种长度各 600 张，训练与

`948ac7be8c4d89e5a48a9a476cf2a97ca8a31c5d1dafa0937b4d799d6bb73ec6`。

### CNN + BiLSTM + CTC 实验

第三阶段模型现支持 `sequence_model=cnn|bilstm`，默认 `cnn` 保持历史checkpoint兼容。BiLSTM版本在
`[B,22,64]` CNN视觉序列后加入一层、每方向 hidden size 64 的双向 LSTM，拼接为 `[B,22,128]` 后
映射到 21 类CTC logits；输出形状仍为 `[B,22,21]`，参数量从 107,669 增至 175,573。训练CLI通过
`--sequence-model bilstm --lstm-hidden-size 64` 启用，并与V2数据、BatchNorm训练集重校准和自动学习率
兼容。checkpoint新增模型架构元数据；评价与验证错误分析会自动按元数据重建模型，同时旧checkpoint缺少
该字段时仍默认加载纯CNN。首个CRNN对照保持20轮、batch size 16、初始学习率0.001、weight decay 0、
seed 0、贪心解码和模型选择规则不变，只增加BiLSTM序列层。

首个BiLSTM实验在第15轮后由调度器把学习率从0.001降至0.0003，并在第18轮取得最佳结果：训练准确率
99.93%、CER 0.02%，验证准确率93.60%、CER 1.70%，按长度为96%、98%、100%、98%和76%，
泛化差距6.33个百分点。相比V2纯CNN自动调度模型，验证准确率提高11.60个百分点、CER降低4.10个
百分点，全部长度分别提高12、14、18、10和4个百分点；也全面超过V1的86.00%/4.30%。这确认显式双向
序列上下文是当前任务的关键缺失模块。当前共享checkpoint SHA-256为
`347a6037f24b5750681cda495e1a3fe14b3fb2485b7095a1276ea199df0811b1`。

BiLSTM验证错误分析只剩16个错误字符串和17次编辑，其中替换/删除/插入为14/3/0；相比自动调度纯CNN
分别减少29个错误字符串、41次编辑、27次替换和14次删除。`m↔n` 从13次降到2次，连续重复字符从
30/39提高到33/39。剩余错误高度集中于六位：12/16个错误来自六位，六位12个错误的编辑距离都恰好为1，
全部3次删除也都发生在六位；2～5位合计只错4个字符串。下一步适合保持权重不变，对比CTC贪心解码与
无语言模型的prefix beam search，检验汇总多条CTC路径能否修复密集六位和重复字符错误。

评价与错误分析入口现支持 `--decoder greedy|beam --beam-width N`。prefix beam search在log-space中分别
累计前缀以blank和非blank结尾的概率，正确处理重复字符必须经blank扩展的CTC规则；第一版固定beam width
为10且不加入语言模型。BiLSTM checkpoint的beam-10结果与greedy完全一致：250个验证样本的全部预测、
16个错误明细、93.60%准确率、1.70% CER、六位76%和重复字符33/39均无变化。因此剩余错误不是贪心只取
单条路径造成的，当前模型在这些样本上已经让错误字符串成为汇总路径概率最高的候选；继续扩大beam而不增加
新信息缺乏依据。

### 提高CTC时间分辨率实验

第三阶段模型现支持 `--sequence-width {22,45}`，默认22兼容历史checkpoint。T=45模式把四块CNN中第三个
池化层从 `(2,2)` 改为 `(2,1)`，只继续压缩高度而保留宽度，使瓶颈输出由 `[B,64,3,22]` 变为
`[B,64,3,45]`，BiLSTM和CTC时间轴相应由22增至45；模型参数量保持175,573不变。训练配置、BatchNorm
校准副本和checkpoint架构元数据均记录该选项；旧checkpoint缺少字段时默认按22重建。首个T=45对照继续
使用V2数据、BiLSTM hidden size 64、20轮、batch size 16、初始学习率0.001、weight decay 0、seed 0、
BatchNorm训练集重校准、自动学习率和greedy解码，只改变时间分辨率。目标是改善当前集中于六位的12个近失
错误，尤其3次删除和连续重复字符。

首个T=45实验训练20轮后只达到训练45.13%/CER 21.93%、验证36.40%/CER 26.30%，按长度为78%、
48%、30%、24%和2%。但这不能解释为更高时间分辨率造成泛化退化：训练集本身尚未拟合，验证loss从
3.4063持续降到0.8120，第20轮仍在明显改善，调度器从未触发，学习率始终为0.001。T=45把每个样本的
CTC路径从22步扩展到45步，增加了blank位置和可行对齐数量，使从随机初始化发现单调对齐显著变慢；相同20轮
不再构成与T=22相同的优化进度。当前共享checkpoint为第20轮T=45模型，SHA-256为
`72d7434b94e7913dd32d12d426b500943e76510f4729dd1241785c63b8e6ec82`。下一步应先解决如何从该checkpoint
延续训练并保留优化器/调度器状态，再判断T=45的最终泛化能力，而不是对欠拟合模型做错误类别分析。

随后从相同seed随机初始化完整训练40轮。T=45在第32轮后把学习率降至0.0003、第38轮后降至0.00009，
最终已充分拟合；最佳第39轮训练准确率99.50%、CER 0.12%，验证准确率87.60%、CER 3.90%，按长度为
96%、94%、92%、92%和64%，泛化差距11.90个百分点。相比T=22 BiLSTM的93.60%/1.70%，总体低6个
百分点、CER高2.20个百分点；2位相同，3/4/5/6位分别低4/8/6/12个百分点。尤其六位从76%降到64%，
否定了增加到45个时间步能改善密集长序列的假设。更多横向位置虽保留细粒度特征，却也减少池化带来的平移
稳定性、扩大CTC对齐空间并增加过拟合自由度；当前任务中T=22是更有效的压缩。共享checkpoint现为第39轮
T=45模型，SHA-256为 `640634e7abb17a8ba11cb7c17682609af62dd04332f8c58ca6b98514a9fb002e`。

### 六位标签加权采样实验

训练入口现支持 `--length-6-weight`，默认1.0时保持原来的无放回shuffle；设为2.0时使用固定seed的
`WeightedRandomSampler`，每轮仍有3000次抽样且采用有放回采样，六位样本的单次权重是其他长度的2倍。
由于V2五种长度原本各600张，理论每轮分布由各600变为六位约1000、其他长度各约500；seed 0的一次抽样
得到2/3/4/5/6位分别485/491/545/471/1008，总数仍为3000。因此20轮仍是60000次样本呈现，没有用更多
总训练预算，只把约400次/轮更新从2～5位重新分配给六位。首个对照恢复T=22、BiLSTM hidden size 64，
其余继续使用V2、20轮、batch size 16、初始学习率0.001、weight decay 0、seed 0、BatchNorm重校准、
自动学习率和greedy解码。目标是在不明显损害2～5位的前提下把六位从76%提高，并观察总体93.60%是否保持。

2倍六位加权实验最佳第19轮：训练准确率99.83%、CER 0.04%，验证准确率92.40%、CER 2.10%，按长度为
98%、94%、96%、96%和78%，泛化差距7.43个百分点。相比未加权T=22基线，总体下降1.20个百分点、CER
增加0.40个百分点；2/3/4/5/6位分别变化+2/-4/-4/-2/+2个百分点。六位只增加1个正确样本，同时2～5位
合计净减少4个正确样本，总正确数从234降到231，因此固定预算下的2倍过采样未成功。结果说明六位额外更新
有轻微收益，但通过有放回抽样减少其他长度覆盖率的代价更大；不继续提高该权重。当前共享checkpoint为第19轮
加权T=22模型，SHA-256为 `2157292f13aa80f710cb9f6faa972f2409fb20e3cfee1c2ef06a151a1b818c6e`。
进一步计算表明，有放回权重抽样每轮预计只覆盖约1844张不同图片：每个2～5位长度约339/600张，六位也只
约487/600张；六位1000次抽样中包含大量重复，并没有覆盖全部六位图片。因此该结果否定的是这一采样策略，
尚不能单独否定“增加六位梯度权重”。更干净的后续对照应恢复每轮全部3000张各出现一次，仅在CTC逐样本
loss聚合时给六位乘2，再按权重和归一化，从而保持数据覆盖、batch数量和总计算量不变。

### 六位逐样本CTC loss加权实验

训练入口现支持 `--length-6-loss-weight`，默认1.0与PyTorch标准CTC mean reduction等价。实现先用
`reduction=none` 得到每个样本的CTC loss，再除以各自目标长度保持历史归一化语义，最后按正权重加权并除以
权重和；设为2.0时只有六位样本权重为2，其余为1。训练DataLoader恢复 `length_6_weight=1.0` 的无放回
shuffle，因此每轮完整覆盖全部3000张不同图片；只有反向传播目标被加权，训练集评价、验证集评价、模型选择、
BatchNorm重校准和学习率调度仍使用标准无权重口径。首个对照固定T=22、BiLSTM hidden size 64、20轮和
其余最佳配置，检验六位梯度强调本身能否在不牺牲2～5位数据覆盖的前提下超过76%及总体93.60%。

六位loss权重2实验最佳第18轮：训练准确率99.90%、CER 0.03%，验证准确率94.00%、CER 1.60%，按长度为
96%、100%、96%、94%和84%，泛化差距5.90个百分点。相比未加权T=22基线，总体提高0.40个百分点、CER
降低0.10个百分点、六位提高8个百分点；2/3/4/5/6位分别变化0/+2/-4/-4/+8个百分点。六位多4个正确
样本，3位多1个，而4位和5位各少2个，最终总正确数从234增至235。该结果达到总体与六位双重成功标准，且
明显优于有放回过采样的92.40%/2.10%，确认完整数据覆盖下的目标加权比样本重复更有效。当前共享checkpoint
为第18轮loss加权T=22模型，SHA-256为 `2e9b08232026fc53be4a41f01bc2159d7b35c17f1609e458eb6d0dc3131921ea`。
错误分析显示15个错误字符串、16次编辑，全部为替换，删除和插入均为0；相比未加权T=22，六位错误从12降到
8、六位编辑距离从12降到8，3次删除全部消失，连续重复字符从33/39提高到36/39并超过V1的34/39。
代价是替换从14增到16，主要体现为少量错误从4～5位重新分配。结果确认loss加权准确击中了六位对齐和重复
字符问题，但剩余瓶颈已转为分散的视觉替换，而非CTC删除。抽查错误图像也支持该判断：`cgca`首字符受到
粗字体和遮挡影响而被判为6，`6p`中的p被干扰线穿过，`23`中的3与圆弧重叠，`nm73`中的n/m细字体相似，
`58a544`中的4被斜线遮挡。错误不再集中于统一序列机制，而是分散于字体、低对比度和干扰线组合。

### 第三阶段阶段性结论

第三阶段已经完成从固定长度分类到可变长度序列识别的学习闭环：CNN把图片转换为22步横向视觉序列，CTC
负责无字符框对齐，BiLSTM提供双向序列上下文，贪心和prefix beam search提供两种解码路径。测试集在全部
模型选择、诊断和实验中保持冻结，当前仍未读取。

本阶段最强配置为V2训练集、T=22、单层双向LSTM（每方向hidden size 64）、六位逐样本CTC loss权重2、
Adam初始学习率0.001、weight decay 0、batch size 16、seed 0、训练集BatchNorm重校准、
`ReduceLROnPlateau`和greedy解码。最佳第18轮验证准确率94.00%、CER 1.60%，按长度为96%、100%、
96%、94%和84%；连续重复字符36/39正确，删除和插入均为0。共享checkpoint SHA-256为
`2e9b08232026fc53be4a41f01bc2159d7b35c17f1609e458eb6d0dc3131921ea`，文件本身按项目规则不提交Git。

已确认有效的改动包括BiLSTM序列建模、训练集BatchNorm统计重校准、后期自动降低学习率，以及在完整数据
覆盖下提高六位CTC loss权重。已否定或不再继续的方向包括 `weight_decay=0.0001`、无语言模型beam-10、
把时间步从22增加到45，以及有放回的六位2倍过采样；固定双渲染V2对纯CNN不利，但在BiLSTM下成为当前
训练基底。最终错误已从序列删除和重复字符问题转为15个分散视觉替换，没有单一高频混淆值得继续专项调参。

本项目主要目标是学习模型结构与训练机制，而不是为实际部署持续堆数据刷指标。因此第三阶段到此停止增加
训练集数量和准确率微调；后续学习可在相同数据上进入Transformer Encoder + CTC，对比递归序列建模与
自注意力，但不属于本阶段提交范围。
